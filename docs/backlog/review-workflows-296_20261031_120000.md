# Review-automation workflows from the BlueprintX scaffold (#296)

Source: `blueprintx/templates/python-common/` (read only). None of the target files existed on
`origin/main` before this branch.

## Imported

- [x] `.github/workflows/coderabbit_trigger.yaml` — CodeRabbit refuses automatic reviews here
  (fewer than 10 stars, refusal notice on #291), so `auto_review` never fires. The request is
  posted with the existing `GH_PAT_REVIEW_TRIGGER` user PAT. Fork PRs are skipped.

## Dropped as duplicates

- [x] `pr-reconcile.yaml` + `bin/pr_reconcile.sh` — same job as the existing
  `reconcile-merged-prs.yaml` + `bin/reconcile_merged_prs.py`, which has the same triggers
  (`closed` + a daily sweep + dispatch). The existing one is unit-tested
  (`tests/unit/test_reconcile_merged_prs.py`) and also refuses to delete the default branch.
  Two workflows would race on the same issues and branches.
- [x] `pr-gate.yaml` — left unchanged. The template's `pr-gate.yaml` / `bin/pr_gate.py` are
  older than this repo's own gate (sticky comment, in-run polling, native auto-merge hand-off).
  None of the imported workflows labels the PR, comments on it, or arms auto-merge, so nothing
  gets gated twice.

## Deferred — depends on files outside this issue's surface

- [ ] `review_threads.yaml`, `review_retry.yaml` + `bin/retry_rate_limited_review.py`, and
  `bin/rerun_stale_gate_runs.sh` all depend on `bin/check_review_threads.py` (2,122 lines,
  from `templates/common/bin/`) and its reviewer roster, `.review-bots.yaml`. Neither file
  exists in this repo, and neither is in #296's surface. Imported without them,
  `review_threads` would go red on every PR and `review_retry` would exit 0 having done
  nothing. They are tracked in a follow-up issue whose surface includes the gate, its roster
  and its tests.

## Gate parity

- [x] No new lint/test gate. `coderabbit_trigger` is a PR automation, not a check that
  pre-commit could run (it needs the PR and a secret), so it has no matching hook. The new
  YAML is already covered by the existing `lint-yaml` / `lint-actions` hooks and CI steps.
